Hiss

This is not mature enough to be open-sourced yet, but hopefully will be in time.

Current future plans, in approximate order:

  • fix macros to make them more robust, maybe even make them Turing-complete
  • make errors better, particularly within macros
  • post-macro compilation should be a bit better at differentiating keyword tokens from things that just "look like that"
  • make "modules" a thing: json header data produced from transpiling a file should have all the info needed to include that as a module elsewhere
  • get some incremental compilation going
  • actually expose the whole type system to the user (currently only partial)
  • better string handling than C

Hiss is a language written in S-expressions (or as they should be properly called, "hiss-expressions") that compiles to C, and apart from the S-expression syntax reads very similarly to C.

  • Targets a small subset of the C language
  • Type-safer than C: almost no implicit casting by default
  • User-defined type system: a type is almost any string, and the rules for implicit conversions and static resolution are editable by the user.

This last property is the main offering of Hiss. For example, you can have a type :Vector and another type :Vector-int, which we will interpret as a vector having int-typed data. These different Hiss-types both have the same underlying C-type, namely struct Vector.

Then any function that accepts a :Vector should always accept a :Vector-int without complaint, and vec_at (getting the ith element of the vector) should return an object of Hiss-type :int. (Hiss-types always begin with a colon to distinguish them from C-types.)

We can implement this easily: using the :: operator gets the type, which we can split out to get the int part.

Here is a sample which defines a struct Vector. As required, if you declare a (vec_new int) and then try to (vec_push v 0.5) you will get a compile error since a double is not an int (and Hiss doesn't do implicit numerical conversion).

(include stdlib)
(include string)

; define a struct with 4 elements
(struct Vector
    :void* data
    :size_t siz
    :size_t len
    :size_t mlen
)

; takes one argument of size_t
(defn :Vector Vector_new :size_t siz {
    (struct_Vector (malloc (* siz (:size_t 2))) siz (:size_t 0) (:size_t 2))
})

(defn :void* Vector_at :Vector* self :size_t i {
    (-<> self->data (at (* i self->siz)) &)
})

(defn :Vector* Vector_push :Vector* self :void* data {
    (if (>= self->len self->mlen) {
        (setv self->mlen (* self->mlen (:size_t 2))
              self->data (realloc self->data (* self->mlen self->siz)))
    })
    (memcpy (->at self self->len) data self->siz)
    (++ self->len)
    self
})

(defmacro vec_new ctype ((## :Vector- ctype) (Vector_new (sizeof (## : ctype)))))
(defmacro vec_at vec idx (-<> (.at vec (:size_t idx)) ((## : (#get 1 (#split (:: vec) -)) *)) *))

(defmacro vec_push vec value {!
    (setv (## : (#get 1 (#split (:: vec) -))) vec_push_special value)
    (.push vec (-<> vec_push_special & :void*))
})

(defn :int main {
    (setv : myvector (vec_new int))
    (vec_push myvector 5) ; okay
    (vec_push myvector 8.3) ; compile error
})

This errors as expected:

ERROR at line 42
>     (vec_push myvector 8.3) ; compile error
 in function main in expansion of macro vec_push: Cannot assign to variable of type :int from source of type :double

This code is a bit janky and the syntax could probably be a bit nicer.

Also the macro kludging is pretty painful: split on -, take the second value, concatenate with : to get the correct inner type.
