Villagers: Economy simulator

[Note: below is a guideline for something I'm thinking about doing. Most of it is not implemented yet.]

[Another note: this project has nothing to do with LLMs or "modern" AI.]

Intro

One thing that has always bugged me about fantasy map generators is that they don't make sense. The target of this project is to create an environment that has agents that are "living" enough to make their own roads, houses, well, etc; to farm their own land; and to generally change their environment to suit them better, according to some reasonable desires.

This requires multiple agents working in concert, but also necessarily making choices justified by their own desires. The only way I can think of to implement this is to have agents interacting through a shared economy, and picking tasks to do at each moment that are maximally rewarded by current commodity prices.

The central efficiency gain the commodity trading provides over each agent acting completely individually is the economy of scale. If each agent would like to eat an onion and sleep under a roof, it is better to split into "onion-gatherers" and "roof-builders", and have the two groups trade with each other, rather than every agent performing both gathering and roof-building. The idea behind this is that doing anything more than once is less costly (in terms of time and effort) than doing it once, per unit produced.

Instead of bartering between commodities directly, there are auctions for commodity futures, and the prices set by these auctions dictate whether an agent will choose to fulfil an onion-gathering order (thereby lowering the price of onions) or something else.

Onions are the canonical food source because onion futures trading is funny.

The current plan is split into several moving parts.

World simulation

There has to be a world in which the agents can act. It has to at least in theory be possible for agents to separate out tasks for efficiency gains.

I'm working on a hiss version of this now.

Planning

The easy version of this is: given fixed prices pcommodityp_{\text{commodity}}pcommodity​ for every commodity (or even for every commodity future for every future delivery date), what is the optimal thing for the agent to do? In the onion gathering case above, the agent has to at least be able to pick some number of onions to gather, which may be 000. The cost of gathering NNN onions is sublinear (this is the central assumption that allows efficiency gains); but there may not be any NNN for which the total gathering cost is less than NponionNp_{\text{onion}}Nponion​.

This is a discrete optimisation problem, and is therefore "hard". It is an open question whether we can find some reasonable heuristics for it.

Trading

Once the agent has decided on a plan, it can submit orders as needed to fulfil the plan. The less trivial part of this is that the agent should also put in orders for unfulfilled plans, to show interest at some price. Initially all order books are empty, so the agent will plan to gather onions themselves; but they will also put in a buy and sell order, at prices at which they would be willing to make that trade instead of their current plan.

This is slightly finnicky and has lots of edge cases, but I have a python implementation of this.
