My Favourite Theorem

Warning: this post spoils the last question of the third-year undergraduate logic and set theory course I took, and it might spoil yours. Read at your own risk!

With my theorem prover PAPA, I proved a theorem that I was so proud of I got two T-shirts with the statement printed on them. The theorem says:

(
  (∀x1 (∀x2 (∃y P[x1,x2,y]))) ∧ 
  (∀x1 (∀x2 (∀y1 (∀y2 (P[x1,x2,y1]⇒(P[x1,x2,y2]⇒(y1=y2)))))))
)
⇒
(∀x (∀n (∃y (∃m (∃a (∃b (
  mod[m,a,x] ∧ 
  (mod[m,a+(b⋅n),y] ∧ 
   (∀i (
     (i<n) ⇒ P[Mod[m,a+(b⋅i)],Si,Mod[m,a+(b⋅Si)]]
   ))
  )
)))))))

I copied the above statement directly from PAPA, only adding indentation (you can find the theorem youself by importing recursion, and expanding the definitions of func2 and recur from the theorem called recursion exists).

This post is an attempt to explain the theorem: what it means, why I care, and why the version on my T-shirts is actually slightly different.

Learn to read

Theorems in PAPA should be read aloud. Parentheses (brackets) are used to group things together, so when reading aloud you should say everything within a pair of brackets really fast, so the listener knows they go together.

The funny looking symbols ∀ and ∃ are quantifiers. The former looks like a rotated A, and should be read "for all" or "for any". The latter looks like a rotated E, and so should be read "there exists".

For all what? What does there exist? In this case, we are talking about whole numbers that are at least 0. That is, the numbers 0, 1, 2, and so on. We don't care about -10, or 3.75.

So (∀x (∃y (y = x + 1))) should be read as "for all xxx, there exists a yyy, such that [deep breath] y=x+1y=x+1y=x+1". Is this a true statement? For sure! You can always add one to a number.

What about if we swap xxx and yyy in the inner bit? Then we have (∀x (∃y (x = y + 1))). Is this true?

If you think about it, this is saying you can always subtract on from a number. Usually this is true, but in our case we can't keep going down forever - we have to stop at 0! So actually this is a false claim, because it's not true for all xxx: it fails when x=0x=0x=0.

Learn to read, part 2

Two other connecting symbols you can see in the above theorem are ∧ ("and") and ⇒ ("implies"). The first you can remember because it looks like the n in "and"; the second is supposed to be like an arrow from the requirement to the result. X ⇒ Y can be read aloud as "X implies Y", or "if X then Y".

Here is an example that shows both: (P ∧ Q) ⇒ P. This says that "P and Q" implies "P"; or put another way if both PPP and QQQ are true statements, then PPP must be a true statement.

So the above theorem has two requirements (first section), and if they are both true, then the second section must be true.

The second section has a bunch of "for all" and "exist" bits, and then has three results connected by an "and".

The last "base symbol" is the S which stands for successory; Sn just means (n+1), the number after n.

Learn to read, part 3

There are only three missing bits now: what are P, mod and Mod?

They are actually two different "types" of thing, analogous to programming types if that is familiar to you.

P and mod are called "relations", and they both have three parameters: there are 3 numbers in the square brackets after them (this is also called having arity 3). Taking the first example above we have P[x1,x2,y]. The thing about relations is that they are always either true or false; so P[x1,x2,y] is either true or false. P itself represents a thing that, for any three numbers, will be either true or false. (It is a function from N3→{true,false}\mathbb N^3 \rarr \{\text{true}, \text{false}\}N3→{true,false}.)

When is P true and when is it false, you might ask? I.e. for which triples of numbers?

In this case (and in all cases involving "generic" relations P, Q, R etc in PAPA), the theorem is true for any P. You can sort of think of the whole statement as being wrapped in a ∀ P (...). Of course you can't really do that within the language because P isn't a number, it's a relation.

So the way to think about this is that for any relation P which satisfies the first section, it must also satisfy the second section.

mod is also an arity-3 relation, the same as P. But in this case it is a specific one that I can tell you: mod[x,y,z] is short for (z<y)∧(∃n (x=((n⋅y)+z))). This is supposed to be the % operator from programming; it is true exactly when zzz is the (unique) number from 000 to y−1y-1y−1 which is the remainder of xxx when divided by yyy.

So you should read mod[x,y,z] as x%y=z or "z is the remainder of x/y". So mod[5,3,2] is true, while mod[5,3,any other number] would be false.

Lastly we have Mod which is a different "type" of thing: instead of taking 3 numbers and producing true or false, it takes two numbers and produces another number. (It is a function from N2→N\mathbb N^2 \rarr \mathbb NN2→N.)

As you might be able to guess, this is the % function we were just talking about - this is just another way of describing the same thing as mod.

(Mod has the extra property that if the second argument is 0 then it returns 0; mod has nothing for that case.)

Let's do some reading

The theorem is split into two sections. The first section has two statements:

"For all x1 and x2, there is a y such that P[x1,x2,y]"

"For all x1, x2, y1, y2: IF P[x1,x2,y1] AND P[x1,x2,y2] THEN y1 and y2 are the same number"

These are saying that for each x1 and x2, there is one (and only one!) y that makes P[x1,x2,y] true. The first statement says there is at least one y that works; the second statement says there is at most one y that works. Put together there must be exactly one.

This y can be different for different x1 and x2! But it can be anything you want.

So to summarise the first section: P has to describe a relation where for any x1 and x2 there is a unique y that makes P true.

Let's do some reading, part 2

Let's ignore the "for all" and "there exists" bits in the second section and go for the three inner statements. I'm going to use % for the mod bits because it's quicker. Then we have:

m % a = x

m % (a + bn) = y

"For all i<n, we have a fact about m % (a + b(i+1)): it's the (unique) thing that makes P true, when its first two arguments are m % (a + bi) and i+1"

Looking at this for a moment you can see that there is a lot of mention of m % (a + bi) for various numbers i: we have 0, n, and then any number between 0 and n (inclusive because we talk about i+1). Let's just call these numbers a0,a1,...,ana_0, a_1, ..., a_na0​,a1​,...,an​ for the moment.

So we're saying: x=a0x = a_0x=a0​; y=any = a_ny=an​; and P[ai,i+1,ai+1]P[a_i, i+1, a_{i+1}]P[ai​,i+1,ai+1​].

Remember all of this is conditional on the first section being true, and that just said that the third argument of PPP is uniquely defined by its first two. So ai+1a_{i+1}ai+1​ is what you "get out" when you "put in" (ai,i+1)(a_i, i+1)(ai​,i+1) into PPP.

So we're starting with a0a_0a0​, then we put (a0,1)(a_0, 1)(a0​,1) into PPP and get a1a_1a1​; then we put that and 2 into PPP to get a2a_2a2​; then we put that and 3 into PPP to get a3a_3a3​; and so on. After nnn of these we have ana_nan​, and we want that to be our yyy.

So all of this is really just saying: "yyy is what you get when you start with xxx, and repeatedly "apply" PPP, nnn times, also giving it i+1i+1i+1 at time iii".

This is a really nice statement to have, and is the central part of what the theorem is trying to do. Maybe now you can see why this module is called recursion.

Let's do some reading, part 3

You might notice something interesting about that last statement we have: it didn't mention, mmm, aaa or bbb at all, even though they were used a lot in the definition.

Because of this, if you have any mmm, aaa and bbb which make that statment true, then it is true!

So we can wrap the whole thing in "there exist m, a and b such that (...)", and it just means what we want. If you can find numbers for these that make the inner statements true, then we have our nice recursion statement.

So, to summarise: the whole statement says, in plain words: "if P defines a function (i.e. last argument uniquely determined by first two arguments), then for any x and n, there is a y which is the result of "applying" P n times to x (and also giving P the index of how far through the repeated applications you are)".

Hang on! you might say, we definitely know that we can always do recursion, but how do we know we can always find the necessary mmm, aaa and bbb? Isn't that much harder?

The answer is yes it is hard, but these numbers will always exist by the Chinese remainder theorem. In a later post I might explain that and go through the PAPA proof of this statement, but for now rest assured that this is definitely true even though it might seem bizarre.

That seemed difficult

I know you're thinking it:

Why go to all this trouble? Surely it's obvious that you can repeatedly apply functions to things? E.g. when defining a factorial, you start with 1 and repeatedly multiply by all the numbers ≤n\leq n≤n. This obviously fits in the recursion theorem above, but when we talk about factorials we never mention modulo or the Chinese remainder theorem.

Very true! When you're thinking about maths in your head, you don't have the same limitations that a theorem prover has. One strong limitation of Peano Arithmetic (which PAPA uses as its base) is that it can't reason about sets or sequences of numbers very easily. In fact, this theorem is sort of the way to start doing that.

Couldn't you just add this theorem as an axiom then, and save yourself the trouble?

Yes but I didn't want to. What next, add Fermat's Last Theorem as an axiom just because it's true? You have to draw the line somewhere.

Good point.

Thank you.

The T-shirt

I might put up a picture of the T-shirts at some point. I actually ordered the shirts before I proved the recursion theorem, and then found a bug in PAPA which meant I could prove false theorems (gasp!), so I spent a long plane flight fixing the bug, fixing all the theorems that relied on the buggy feature which was almost all of them, and then proving the rest of the recursion theorem. By far it was the most productive I have ever been on a plane.

But the T-shirt actually has a stronger statement that only asks for existence of PPP not uniqueness (i.e. drops the second line in the first section). This statement is still true because you can allways "uniqueify" PPP, but you can't prove it directly: you have to go through the weaker statement first. (TL;DR the reason is because without uniqueness you can't bound how large yyy can get, which you need when proving the existence of mmm.)

I still technically haven't proven the stronger version, but it should be easy now I have the weaker one; maybe I'll do it and make a post about it.
